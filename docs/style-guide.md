# Style Guide

Working checklist for the `AGENTS.md` Copy Editor role: terminology
consistency and jargon avoidance across every chapter.

## Terminology

- Use vocabulary terms exactly as spelled in `docs/vocabulary.md`
  (e.g. always "Voice-Leader" with the hyphen, always "Push / Lay-back"
  with the slash). Do not introduce synonyms for a defined term —
  if a synonym reads better in prose, it belongs in `vocabulary.md`
  itself as the canonical name, not as a one-off substitute.
- Capitalize a term only when invoking it as a defined concept ("this
  bass line is functioning as a **Connector**"), not when using the
  underlying English word generically ("this note connects the two
  chords").
- Introduce a term once per chapter, at its first use, in bold; do not
  re-bold it on every subsequent mention.

## Jargon

- Avoid scale/mode/arpeggio-first language (the book's Core Promise in
  `BLUEPRINT.md` is explicitly not "which scale should I play"). If a
  scale name is unavoidable, subordinate it to the Role/Motion/Groove
  question it's answering.
- Avoid unexplained genre shorthand (e.g. "on the and of 2") without a
  one-time definition — the audience is intermediate players across
  jazz, funk, fusion, and neo-soul, who won't share one dialect.
- Prefer the term itself over an abbreviation. Only abbreviate a term
  after it has been introduced in full at least once in that chapter.

## Voice

- Second person, direct address ("you"), matching `preface.qmd`'s
  register in the Thinking in Layers companion project.
- One idea per paragraph where possible; this book's pillar is one
  concept per chapter, and that discipline should hold at the paragraph
  level too.

## Cross-references

- Link to another chapter by title and number ("see Chapter 11, The
  Pedal"), not by file path, in prose meant for the reader. File paths
  are for repo-internal docs like this one.
